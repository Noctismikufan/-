## 八、应用题（10 分）

**16.** 某团队要实现两个功能：

- **功能甲**：每天凌晨 2 点，把数据库里的销售数据导出为 Excel，并发送到指定邮箱。
- **功能乙**：用户用自然语言提问"上个月华东区的销售异常在哪里"，系统需要自行判断查哪些表、如何分析、必要时追问用户。

请分别判断这两个功能更适合用**工作流**还是 **Agent**，并说明理由。

# 答案与解析

> ⚠️ 请先独立完成题目后再查看

## 一、单选题

**1.** **B**
**解析**：Agent 的本质特征是**运行时自主决策**（对应"二、核心定义"），而工作流的步骤由人预先写死。A 项错在速度并非本质区别；C 项错在联网只是工具的一种；D 项错在两者通常都依赖大模型。

**2.** **C**
**解析**：Agent = 模型 + 自主循环 + 工具 + 记忆（对应"二、核心定义"）。界面样式与 Agent 的本质无关，很多 Agent 甚至没有界面。

**3.** **B**
**解析**："观察"环节读取工具返回的真实结果，是"反思与调整"的输入依据（对应"三、工作原理"）。它服务于 Agent 自身的决策循环，而非给用户看日志。

**4.** **B**
**解析**：自主性的准确含义是运行时决定下一步（对应"二、核心定义"）。A 项是"过度自主"的误区；C 项错在目标由人设定，Agent 不自行改目标；D 项错在对话界面只是交互形式。

## 二、多选题

**5.** **ABCD**
**解析**：搜索、代码执行、读写文件、调用 API 都是 Agent 常见的外部能力（对应"二、核心定义"中"工具"的说明）。

**6.** **ABC**
**解析**：A、B 是 Agent 与工作流的核心区别；C 正确，实际系统常混合两者（对应"七、相邻概念"）。D 错误——Agent 的关键是运行时自主决策，不是"步骤更多"。

## 三、判断题

**7.** **✗ 错误**
**解析**：这是典型误区（对应"六、常见误区"）。聊天只是交互形式之一，Agent 的本质是能自主行动和调用工具，很多 Agent 没有对话界面。

**8.** **✗ 错误**
**解析**：LLM 是 Agent 的一个组件（大脑），Agent 还需要工具、记忆和调度循环（对应"七、相邻概念"）。

**9.** **✗ 错误**
**解析**：如果每一步都由人预先写死，那是**工作流**而非 Agent（对应"六、常见误区"）。关键在决策发生在运行时还是设计时。

## 四、填空题

**10.** **ReAct**
**解析**：ReAct = Reasoning + Acting，是最经典的 Agent 循环框架（对应"三、工作原理"）。

**11.** **记忆**
**解析**：记忆负责保存历史步骤和中间结果（对应"二、核心定义"）。

## 五、简答题

**12.**
**参考答案**：反思与调整环节让 Agent 根据工具返回的**真实结果**修正自己的计划，而不是一条道走到黑。例如搜索到的是旧闻时，它能修改关键词重新搜索。
若没有这个环节，Agent 就退化为"按预设顺序执行一次工具调用"，失去了根据反馈纠错的能力，本质上成了工作流，无法应对执行过程中出现的意外情况。
*（对应"三、工作原理"）*

**13.**
**参考答案**：Agent 的自主决策可能陷入死循环（反复尝试同一个失败方案），或执行过多步导致成本失控。设置步数上限能强制终止异常运行，避免资源浪费，也降低 Agent 误操作的风险。这是当前 Agent 安全设计的常见做法。
*（对应"六、常见误区"中"完全自主不需要人管"的辨析）*

## 六、连线题

**14.**
- Agent → **b**
- 工作流 → **a**
- 工具调用 → **c**

**解析**：Agent 与工作流的核心区别在决策时机（运行时 vs 设计时）；工具调用是 Agent 的一项能力，单次调用不构成 Agent（对应"七、相邻概念"）。

## 七、辨析题

**15.**
**参考答案**：这个说法不成立。
"自主"指的是 Agent 能在运行时决定**如何达成目标**，不等于取消一切边界。目前绝大多数 Agent 都需要设定目标、限定工具范围、设置步数上限和安全边界。
原因在于 Agent 的"自主"本质是概率性的文本生成，可能自信地做出错误决策，甚至误删文件、乱发消息。完全自主反而危险。因此"自主"与"受控"是并存的：在**方法**上自主，在**边界**上受控。
*（对应"六、常见误区"）*

## 八、应用题

**16.**
**参考答案**：
- **功能甲适合工作流**。它的步骤完全固定、无分支判断：定时触发 → 导出 → 发送，路径在设计时就确定，不需要运行时决策。用工作流更稳定、可预测、成本更低。
- **功能乙适合 Agent**。用户的问题开放，"查哪些表、如何分析"无法预先写死，还可能需要在信息不足时追问用户。这需要运行时自主规划与动态调整，正是 Agent 的适用场景。

**判断依据**：决策发生在**设计时**（工作流）还是**运行时**（Agent）。
*（对应"六、常见误区"中"多步执行就是 Agent"的辨析）*
