# 答案与解析

> ⚠️ 请先独立完成题目后再查看

## 一、单选题

**1.** **B**
**解析**：Skill 是打包好的、可按需加载的专业能力模块（对应"二、核心定义"）。A 项是提示词；C 项混淆了 Skill 与脚本（Skill 本身不执行）；D 项错误。

**2.** **B**
**解析**：第 1 级是**名称 + 描述**，始终在上下文中，约 100 词（对应"三、工作原理"的加载表）。

**3.** **B**
**解析**：按需加载的核心目的是节省上下文（对应"三、工作原理"）。若有大量 Skill 全部常驻，会直接撑爆上下文窗口。

**4.** **D**
**解析**：Skill 的可选资源是 `scripts/`、`references/`、`assets/` 三类（对应"二、核心定义"）。`weights/` 是模型参数，不属于 Skill。

## 二、多选题

**5.** **ABC**
**解析**：Skill = 元数据 + 操作指令 + 可选资源（对应"二、核心定义"）。D 错误——Skill 没有独立运行时进程，它只是给 AI 的说明书。

**6.** **ABC**
**解析**：A、B、C 正是 Skill 解决的三个问题（对应"一、它解决什么问题"）。D 错误——Skill 不会改变模型参数。

## 三、判断题

**7.** **✗ 错误**
**解析**：提示词模板只是一段文字；Skill 是完整目录结构，含元数据、正文、可执行脚本、参考文件，并遵循按需加载机制（对应"六、常见误区"）。

**8.** **✗ 错误**
**解析**：Skill 本身不执行任何东西，它只是告诉 AI 该运行哪个脚本、读哪个文件；执行动作的是 AI（对应"六、常见误区"）。

**9.** **✗ 错误**
**解析**：平时只有名称和描述（约 100 词）在上下文中，正文和资源按需加载（对应"三、工作原理"）。

## 四、填空题

**10.** **Progressive Disclosure**
**解析**：即"渐进式披露/渐进式加载"（对应"三、工作原理"）。

**11.** **scripts**（或 `scripts/`）
**解析**：scripts 存放可执行的确定性代码（对应"二、核心定义"）。

## 五、简答题

**12.**
**参考答案**：Skill 采用三级渐进式加载：
- **第 1 级**：名称 + 描述，**始终**在上下文中（约 100 词），用于让 AI 判断哪个 Skill 相关
- **第 2 级**：SKILL.md 正文，**判定相关时**才加载（< 5k 词），提供具体操作指令
- **第 3 级**：scripts / references / assets，**真正需要时**才加载，体量不限

这样设计使 Skill 的数量增长不会线性推高上下文占用，从而支持大量 Skill 并存。
*（对应"三、工作原理"）*

**13.**
**参考答案**：
- **工具（Tool）** 是 AI 能调用的**具体功能接口**，如搜索、执行代码、读写文件。
- **Skill** 是**组织知识和流程的说明文档包**，它告诉 AI 在什么场景、按什么步骤做事。
- 二者层级不同：Skill 可能会**指导 AI 去使用某些工具**，但 Skill 本身不是工具。

打个比方：工具是"扳手"，Skill 是"维修手册"——手册会告诉你何时用哪把扳手，但手册本身拧不动螺丝。
*（对应"七、相邻概念"）*

## 六、连线题

**14.**
- Skill → **c**
- 工具 → **a**
- MCP → **b**

**解析**：Skill 是固化流程知识的文档包；工具是可调用的功能接口；MCP 是连接外部服务的协议（对应"七、相邻概念"）。

## 七、辨析题

**15.**
**参考答案**：这个说法不准确，二者有本质区别：
1. **形态不同**：提示词模板是一段文本；Skill 是一个**完整目录结构**，含元数据、正文、脚本、参考文件
2. **加载机制不同**：提示词需每次手动粘贴；Skill 由 AI **按需自动加载**，平时只占约 100 词
3. **可复用与可管理**：Skill 可版本管理、可分发（打包为 zip）、可携带可执行脚本；提示词模板不具备这些能力
4. **能力范围不同**：Skill 能组织"流程 + 资源 + 代码"，提示词只能组织文字

可以说 Skill **包含**了指令性内容，但远不止于一段提示词。
*（对应"六、常见误区"）*

## 八、应用题

**16.**
**参考答案**：
**适合**。理由：该需求的核心是"固定的格式和流程"，正需要把专业流程固化、复用，且要求输出质量稳定——正是 Skill 的适用场景。

**目录结构建议**：
```
weekly-report-skill/
├── SKILL.md                    # 主流程：何时触发、按什么步骤生成周报
│   ├── 说明触发条件（用户要求写周报时）
│   ├── 规定输出结构（本周进展/问题/下周计划）
│   └── 引用下方资源
├── references/
│   └── format-spec.md          # 公司周报格式规范、措辞要求（需要时加载）
└── assets/
    └── checklist-template.md   # 标准数据核对清单模板（作为输出的一部分）
```

**说明**：格式规范放入 `references/` 是因为它是"需要时查阅的资料"；核对清单模板放入 `assets/` 是因为它要**作为输出的一部分被复制使用**。这样 SKILL.md 保持精简，详细内容按需加载。
*（对应"二、核心定义"与"三、工作原理"）*
