# Agent（智能体）

> 一句话定义：Agent 是一个能自主感知环境、规划步骤、调用工具并根据结果调整行动的 AI 系统，而不只是被动回答问题的模型。

## 一、它解决什么问题

大语言模型（LLM）本身只会做一件事：**给定输入，输出文本**。它不能上网查资料、不能操作文件、不能记住上一步做过什么，更不能把一个复杂目标拆成多步去完成。

现实中大量任务恰恰需要这些能力。比如"帮我查一下北京明天的天气，如果下雨就发邮件提醒我带伞"——这需要：查天气（调工具）→ 判断（推理）→ 发邮件（调工具），中间还有条件分支。

**Agent 就是为填补"只会说话"到"能办事"之间的鸿沟而出现的。**

## 二、核心定义

Agent（智能体）= **模型 + 自主循环 + 工具 + 记忆**。

拆解定义中的关键词：

- **模型**：通常是一个 LLM，充当"大脑"，负责推理和决策
- **自主循环**：不是一问一答就结束，而是"思考 → 行动 → 观察 → 再思考"的循环，直到目标达成
- **工具**：模型可以调用的外部能力，如搜索、代码执行、读写文件、调用 API
- **记忆**：保存历史步骤和中间结果，使多步任务能连贯进行

判断一个系统是不是 Agent，关键看它**能否自主决定下一步做什么**，而不是由人把每一步都写死。

## 三、工作原理 / 关键机制

Agent 的典型运作循环（常被称为 **ReAct 模式**，即 Reasoning + Acting 的缩写，意为"推理与行动交替"）：

1. **接收目标**：用户给出一个目标，而非一条指令
2. **规划**：模型分析目标，拆解出需要的步骤
3. **行动**：调用某个工具执行一步（如搜索、读文件）
4. **观察**：读取工具返回的结果
5. **反思与调整**：判断是否接近目标，若未达成则回到第 2 步，重新规划
6. **终止**：目标达成或达到步数上限时输出结果

关键点在于**第 5 步的反馈闭环**——模型会根据真实结果修正自己的计划，而不是一条道走到黑。

## 四、一个恰当的类比

把 Agent 类比成**一个刚入职的助理**：

- 你交代的不是"把这份文件复印三份"，而是"帮我把这次会议的纪要整理好并发给参会同事"
- 助理会自己拆解：找会议记录 → 整理成纪要 → 找到参会人邮箱 → 发送
- 遇到问题时（比如找不到某人的邮箱）会自己想办法，而不是卡住不动

**类比的局限**：真人助理有常识、责任心和真正的理解，而 Agent 的"自主"本质上是概率性的文本生成，它可能自信地做出错误决策，也可能陷入循环。把它当人看会高估它的可靠性。

## 五、具体示例

**示例：一个研究型 Agent 接到任务"总结最近一周 AI 领域的重要进展"**

- 规划：先搜索新闻 → 筛选重要事件 → 逐个查证 → 汇总成文
- 行动：调用搜索工具，得到 20 条结果
- 观察：发现其中几条是旧闻，时间不符
- 调整：修改搜索关键词，加上时间限定，重新搜索
- 最终：筛选出 5 条真正的新进展，生成总结

注意第 4-5 步——**发现结果不理想后自行调整**，这正是 Agent 与"一次性生成"的本质区别。

## 六、常见误区

❌ **误解一**：Agent 就是一个更聪明的聊天机器人
✅ **正解**：聊天只是交互形式之一。Agent 的本质是**能自主行动和调工具**，很多 Agent 甚至没有对话界面（如自动处理数据的后台 Agent）。

❌ **误解二**：Agent = 大模型
✅ **正解**：大模型是 Agent 的一个组件（大脑）。Agent 还需要工具、记忆和调度循环。同一个模型可以驱动不同的 Agent 系统。

❌ **误解三**：Agent 完全自主，不需要人管
✅ **正解**：目前绝大多数 Agent 都需要设定目标、限定工具范围、设置步数上限和安全边界。过度自主反而危险（可能误删文件、乱发消息）。

❌ **误解四**：多步执行就是 Agent
✅ **正解**：如果每一步都是人预先写死的（如固定的工作流），那叫**工作流（Workflow）**，不是 Agent。Agent 的关键是**运行时自主决策**。

## 七、与相邻概念的关系

| 概念 | 与 Agent 的区别 |
|------|----------------|
| **大语言模型（LLM）** | LLM 是"大脑"，Agent 是"有手有脚会办事的整体" |
| **工作流（Workflow）** | 工作流路径预先固定；Agent 路径运行时决定 |
| **工具调用（Tool Use）** | 工具调用是 Agent 的一个能力，单次工具调用不构成 Agent |
| **RAG（检索增强生成）** | RAG 是给模型补充外部知识的技术，可被 Agent 用作一个工具 |

## 八、延伸学习

1. **ReAct 模式**——理解 Agent 最经典的"推理+行动"循环框架
2. **工具调用（Function Calling）**——Agent 与外部世界交互的技术基础
3. **多智能体系统（Multi-Agent）**——多个 Agent 协作完成复杂任务
4. **Agent 的安全与对齐**——如何限制 Agent 的行为边界，防止失控
