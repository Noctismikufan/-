# 大模型的上下文（Context）

> 一句话定义：上下文是模型在生成当前回答时，能够"看到"并加以利用的全部输入信息的总和，它决定了模型此刻"知道什么"。

## 一、它解决什么问题

大模型本身是一个"无状态"的函数：你给它一段输入，它吐出一段输出，然后就**什么都不记得了**。它没有内置的长期记忆，也不会记得你上一次跟它聊过什么。

但人类的对话天然需要连续性——你问"它多少钱？"，必须知道上一句说的是什么东西。同时，模型还需要参考资料、指令、历史对话等额外信息才能答得准。

**上下文机制就是为了把"这次回答所需要的一切相关信息"打包喂给模型。** 模型的表现上限，很大程度上取决于上下文里放了什么。

## 二、核心定义

上下文 = **模型本次推理时可见的全部 token 序列**，通常包括：

- **系统提示（System Prompt）**：设定角色和规则
- **对话历史**：之前几轮的用户输入和模型回复
- **当前用户输入**：这一次的问题
- **外部资料**：检索到的文档、工具返回的结果等

拆解关键词：

- **可见**：只有进入上下文的文本，模型才能"看到"；没进去的，模型一概不知
- **token 序列**：上下文是按 token 计的，不是按字数
- **本次推理**：上下文是**一次性的**，不自动跨轮次保存（需要靠外部机制重新拼装）

## 三、工作原理 / 关键机制

1. **拼接**：系统把各类信息按一定顺序拼成一段长文本，作为模型输入
2. **上下文窗口（Context Window）**：模型一次能处理的最大 token 数，如 8K、128K、200K。超出部分会被截断或丢弃
3. **注意力计算**：模型通过注意力机制（Attention）计算每个 token 与其他 token 的关联强度，从而"利用"上下文
4. **生成输出**：模型基于整个上下文预测下一个 token，逐字生成回答
5. **上下文管理**：在多轮对话中，系统需要决定保留哪些历史、丢弃哪些（如滑动窗口、摘要压缩），否则很快会撑满窗口

**关键限制**：上下文窗口是有限的。塞得越满，不仅成本越高，模型对中间内容的注意力还可能下降（俗称"迷失在中间"，Lost in the Middle）。

## 四、一个恰当的类比

把上下文窗口类比成**一张有限大小的工作台**：

- 你只有把手头的资料**放到工作台上**，模型才能看到并利用
- 台面就那么大，放满了就得拿走一些旧资料
- 放在台面**中间位置**的资料，模型可能没注意到；而最靠近手边（开头和结尾）的反而更容易被用到

**类比的局限**：工作台是静态的物理空间，而真实的注意力机制是**动态加权**的——模型不是简单地"看到/看不到"，而是对每个位置赋予不同的关注权重。此外，类比无法体现 token 计费和窗口超限后的截断行为。

## 五、具体示例

**示例：同一个问题，上下文不同，答案质量天差地别**

场景：你问"总结一下这个方案的风险"。

- **上下文 A**：只发了这一句
  → 模型只能泛泛而谈"方案风险通常包括技术风险、市场风险……"，毫无针对性

- **上下文 B**：先粘贴了完整方案文档，再问同样的问题
  → 模型能指出"该方案在第三阶段的资金回笼周期存在 6 个月的缺口"，具体且有用

**同样的模型、同样的提问，唯一的差别是上下文里有没有那份文档。** 这就是上下文的决定性作用。

## 六、常见误区

❌ **误解一**：上下文窗口越大越好，越大越聪明
✅ **正解**：窗口大只是"能塞更多"，不等于"用得更好"。内容过多会稀释注意力、增加成本，甚至让模型抓不住重点。**相关性比数量重要**。

❌ **误解二**：上下文就是聊天记录
✅ **正解**：聊天记录只是上下文的一部分。系统提示、检索资料、工具返回结果同样属于上下文。

❌ **误解三**：模型会记住上下文，下次对话还在
✅ **正解**：上下文是**单次推理内**有效的。新开一轮对话，之前的内容就不在了，除非系统重新把它们拼进去。模型的"记忆"是靠外部机制（如把历史重新塞进上下文）实现的，不是模型自带的。

❌ **误解四**：上下文和提示词（Prompt）是一回事
✅ **正解**：提示词是**你主动写的那部分指令**；上下文是模型**本次能看到的全部信息**，包含提示词但不限于提示词。提示词是上下文的子集。

## 七、与相邻概念的关系

| 概念 | 与上下文的关系 |
|------|---------------|
| **提示词（Prompt）** | 提示词是上下文的一部分，是你主动构造的指令 |
| **上下文窗口** | 是上下文的**容量上限**，上下文是窗口里实际装的内容 |
| **记忆（Memory）** | 记忆是跨轮次保存信息的**外部机制**，它把内容重新注入上下文 |
| **RAG（检索增强生成）** | RAG 是把外部知识检索出来、放进上下文的**手段** |
| **Token** | 上下文的计量单位，窗口大小以 token 数衡量 |

## 八、延伸学习

1. **注意力机制（Attention）**——理解模型如何"利用"上下文的底层原理
2. **上下文工程（Context Engineering）**——如何设计和管理上下文以最大化模型表现
3. **RAG 检索增强生成**——从外部知识库动态构建上下文的典型方案
4. **长上下文技术**——如何突破窗口限制（如位置编码外推、稀疏注意力）
5. **"迷失在中间"现象**——长上下文中的注意力分布问题
