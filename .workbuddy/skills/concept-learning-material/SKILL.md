# 概念学习资料生成

## 概述

为任意概念生成**结构化、由浅入深、可独立阅读**的中文学习资料，并可选地生成**配套题库**，形成"学 + 练"闭环。目标是让一个没有背景知识的读者，读完能建立正确的心智模型，并通过做题检验掌握程度。

## 何时使用

- 用户说"帮我学习/讲解/梳理 X 概念"
- 用户要求把某个术语整理成笔记、科普、教程、学习资料
- 用户要求为概念出题、生成练习/测验/题库
- 用户一次性给出多个概念要求学习（逐个生成，各自独立成文）
- 课程笔记、知识库建设中需要补充概念词条

不适用：需要实时数据的事实查询、代码调试、非概念性的操作任务。

## 生成工作流

### 第 1 步：概念解析

在动笔前先判断：

1. **概念类型**：技术概念 / 理论概念 / 工具概念 / 抽象方法论。不同类型侧重点不同。
2. **受众层级**：默认假设读者是"有基本计算机素养但不懂该领域"的初学者。若用户指定了层级（如"给小学生讲"），相应调整深度。
3. **概念边界**：明确该概念**包含什么**、**不包含什么**，避免与相邻概念混淆（如 Agent vs 工作流、上下文 vs 提示词）。
4. **是否出题**：判断用户是否需要配套练习题。若用户明确要"出题/测验/题库"，或学习场景适合练习巩固，则生成题库（见第 4 步）。

### 第 2 步：按固定结构输出学习资料

每个概念生成一份独立 Markdown 文件，**严格使用以下结构**（缺一不可）：

```markdown
# {概念名}

> 一句话定义：{用一句话说清它是什么}

## 一、它解决什么问题
{这个概念为什么存在？在没有它之前，人们面临什么痛点？}

## 二、核心定义
{给出严谨定义，并拆解定义中的每个关键词}

## 三、工作原理 / 关键机制
{它内部是怎么运作的？用分点或流程描述}

## 四、一个恰当的类比
{用日常生活或已知事物做类比，帮助建立直觉}
{必须说明类比的局限——类比在哪里会失效}

## 五、具体示例
{给出 1-2 个具体、可感知的例子}

## 六、常见误区
{初学者最容易搞错的 2-4 点，用"❌ 误解 → ✅ 正解"的形式}

## 七、与相邻概念的关系
{它和哪些概念容易混淆？区别是什么？}

## 八、延伸学习
{下一步该学什么？推荐 2-3 个关联概念或方向}
```

### 第 3 步：学习资料质量自检

生成后逐项核对（详见 `references/quality-checklist.md`）：

- [ ] 一句话定义是否**不含**该概念本身的同义词循环（如"Agent 就是一种智能体"属无效定义）
- [ ] 是否有**具体**示例，而非空泛描述
- [ ] 类比是否说明了**局限**
- [ ] 是否区分了易混淆的相邻概念
- [ ] 术语首次出现是否有解释
- [ ] 全文是否无夸张营销式措辞（"革命性""颠覆"等）

### 第 4 步：生成配套题库（可选）

当需要出题时，为概念生成练习题，**题目与答案必须分离**。

#### 题型规范（八种）

| 题型 | 用途 | 标记 | 考查层次 |
|------|------|------|---------|
| 单选题 | 考查定义、特征辨析 | `[单选]` | 记忆/理解 |
| 多选题 | 考查多要素、边界 | `[多选]` | 理解/分析 |
| 判断题 | 考查易混点、误区 | `[判断]` | 理解 |
| 填空题 | 考查关键术语 | `[填空]` | 记忆 |
| 简答题 | 考查机制阐述 | `[简答]` | 理解/应用 |
| 连线题 | 考查概念与描述匹配 | `[连线]` | 理解 |
| 辨析题 | 考查相邻概念区分 | `[辨析]` | 分析/评价 |
| 应用题 | 考查迁移到新场景 | `[应用]` | 应用/创造 |

#### 出题原则

1. **覆盖八节内容**：题目应覆盖定义、原理、类比、误区、相邻概念等各节，而非只考定义
2. **难度递进**：从识记 → 理解 → 应用 → 分析，由易到难排列
3. **干扰项有依据**：错误选项应来自**真实误区**（参考学习资料的"常见误区"节），而非随意编造
4. **避免陷阱题**：不考无意义的文字游戏，不考偏门细节
5. **每题标注出处**：注明该题对应学习资料的哪一节，便于回溯
6. **每题附解析**：答案区必须说明"为什么"，而非只给答案

#### 题库文件结构

题库保存在 `notes/题库/` 目录，**一概念一文件**：

```markdown
# {概念名} · 练习题

> 共 N 题 | 建议用时 X 分钟 | 难度 ★★☆

## 一、单选题（每题 X 分，共 N 分）

**1.** {题干}
A. {选项}
B. {选项}
C. {选项}
D. {选项}

---

## 二、多选题（每题 X 分，共 N 分）

**2.** {题干}（多选）
A. ... B. ... C. ... D. ...

---

（依次为判断、填空、简答、连线、辨析、应用题）

---

# 答案与解析

> ⚠️ 请先独立完成题目后再查看

## 单选题
**1.** B
**解析**：{说明为什么选 B，以及其它选项错在哪}

## 多选题
**2.** ACD
**解析**：{...}

（依次列出各类题型的答案与解析）

---

## 知识点分布表

| 题号 | 题型 | 对应学习资料章节 | 难度 |
|------|------|----------------|------|
| 1 | 单选 | 二、核心定义 | ★ |
| 2 | 多选 | 六、常见误区 | ★★ |
```

#### 题库质量自检

- [ ] 题目与答案**分离**（答案统一放在文末"答案与解析"区）
- [ ] 每题都有**解析**，且解释充分
- [ ] 干扰项来自真实误区，具有迷惑性但不误导
- [ ] 题型覆盖至少 4 种
- [ ] 难度有梯度
- [ ] 题目无歧义（单选题有且仅有一个正确答案）
- [ ] 提供了知识点分布表

## 输出与保存

| 内容 | 位置 | 命名 |
|------|------|------|
| 学习资料 | `notes/` | `{概念名}.md`，如 `notes/Agent.md` |
| 题库 | `notes/题库/` | `{概念名}-练习题.md`，如 `notes/题库/Agent-练习题.md` |
| 多概念 | 每个概念独立成文，不合并 | — |
| 编码 | UTF-8 | — |

## 写作风格要求

- 使用简体中文，技术术语首次出现时附英文原文，如"智能体（Agent）"
- 客观、平实，避免感叹号和营销词汇
- 多用短句和分点，少用长难句
- 由浅入深，先讲直觉再讲严谨定义
- 不编造事实；不确定的内容明确标注"（存在不同说法）"
