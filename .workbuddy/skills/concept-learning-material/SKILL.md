# 概念学习资料生成

## 概述

为任意概念生成一份**结构化、由浅入深、可独立阅读**的中文学习资料。目标是让一个没有背景知识的读者，读完能建立正确的心智模型，并知道下一步该学什么。

## 何时使用

- 用户说"帮我学习/讲解/梳理 X 概念"
- 用户要求把某个术语整理成笔记、科普、教程、学习资料
- 用户一次性给出多个概念要求学习（逐个生成，各自独立成文）
- 课程笔记、知识库建设中需要补充概念词条

不适用：需要实时数据的事实查询、代码调试、非概念性的操作任务。

## 生成工作流

### 第 1 步：概念解析

在动笔前先判断：

1. **概念类型**：技术概念 / 理论概念 / 工具概念 / 抽象方法论。不同类型侧重点不同。
2. **受众层级**：默认假设读者是"有基本计算机素养但不懂该领域"的初学者。若用户指定了层级（如"给小学生讲"），相应调整深度。
3. **概念边界**：明确该概念**包含什么**、**不包含什么**，避免与相邻概念混淆（如 Agent vs 工作流、上下文 vs 提示词）。

### 第 2 步：按固定结构输出

每个概念生成一份独立 Markdown 文件，**严格使用以下结构**（缺一不可）：

```markdown
# {概念名}

> 一句话定义：{用一句话说清它是什么}

## 一、它解决什么问题
{这个概念为什么存在？在没有它之前，人们面临什么痛点？}

## 二、核心定义
{给出严谨定义，并拆解定义中的每个关键词}

## 三、工作原理 / 关键机制
{它内部是怎么运作的？用分点或流程描述}

## 四、一个恰当的类比
{用日常生活或已知事物做类比，帮助建立直觉}
{必须说明类比的局限——类比在哪里会失效}

## 五、具体示例
{给出 1-2 个具体、可感知的例子}

## 六、常见误区
{初学者最容易搞错的 2-4 点，用"❌ 误解 → ✅ 正解"的形式}

## 七、与相邻概念的关系
{它和哪些概念容易混淆？区别是什么？}

## 八、延伸学习
{下一步该学什么？推荐 2-3 个关联概念或方向}
```

### 第 3 步：质量自检

生成后逐项核对（详见 `references/quality-checklist.md`）：

- [ ] 一句话定义是否**不含**该概念本身的同义词循环（如"Agent 就是一种智能体"属无效定义）
- [ ] 是否有**具体**示例，而非空泛描述
- [ ] 类比是否说明了**局限**
- [ ] 是否区分了易混淆的相邻概念
- [ ] 术语首次出现是否有解释
- [ ] 全文是否无夸张营销式措辞（"革命性""颠覆"等）

## 输出与保存

- **保存位置**：默认写入工作区 `notes/` 目录，文件名用概念名，如 `notes/Agent.md`
- **多概念**：每个概念一个文件，不合并
- **命名**：文件名保留概念原语言（如 `Agent.md`、`大模型的上下文.md`）
- **编码**：UTF-8

## 写作风格要求

- 使用简体中文，技术术语首次出现时附英文原文，如"智能体（Agent）"
- 客观、平实，避免感叹号和营销词汇
- 多用短句和分点，少用长难句
- 由浅入深，先讲直觉再讲严谨定义
- 不编造事实；不确定的内容明确标注"（存在不同说法）"
