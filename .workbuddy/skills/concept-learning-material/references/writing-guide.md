# 概念讲解写作指南

## 核心原则：从直觉到严谨

初学者的认知路径是：**先有画面，再有定义**。因此讲解顺序应为：

1. 它解决什么问题（制造需求感）
2. 一个可感知的类比（建立直觉画面）
3. 严谨定义（在直觉之上精确化）
4. 机制细节（深入）
5. 示例验证（落地）

不要一上来就抛定义。

## 各类概念的讲解侧重

| 概念类型 | 侧重 | 举例 |
|----------|------|------|
| 技术概念 | 机制、实现、边界 | 大模型的上下文 |
| 工具概念 | 用途、场景、操作 | Skill |
| 抽象方法论 | 适用条件、权衡 | 提示工程 |
| 系统概念 | 组成、交互、涌现性 | Agent |

## 类比的使用方法

好类比的三要素：

1. **结构对应**：类比对象与概念在结构上相似（不只是表面像）
2. **可延展**：读者能顺着类比推出更多正确结论
3. **明说局限**：明确指出类比在哪里失效

示例（上下文窗口）：
> 上下文窗口像一个"工作台"：桌面就那么大，你放上去的资料模型才能看到，超出桌面的内容它就"看不见"了。局限：工作台是静态的，而真实的上下文机制还涉及注意力权重的动态分配，并非简单"看到/看不到"的二分。

## 误区的写法

用对比格式，冲击力强且清晰：

```
❌ 误解：Agent 就是一个更聪明的聊天机器人
✅ 正解：Agent 的关键在于它能自主规划、调用工具、根据反馈调整——
        "对话"只是它的交互形式之一，不是本质。
```

## 语言风格

- 短句优先，一句说清一件事
- 抽象概念后紧跟一个具体例子
- 慎用形容词，多用动词和名词
- 中英混排：中文与英文之间加空格，如"大语言模型（LLM）的能力"
- 首次出现的术语：中文（English）

## 长度控制

- 单一概念：600–1200 字为宜
- 概念极复杂时可到 1500 字，但必须保证每一节都有信息量
- 宁可精炼也不要注水
